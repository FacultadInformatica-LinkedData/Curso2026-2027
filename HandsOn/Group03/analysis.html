Analysis Callejero de Madrid

Data analysis

  • File format: CSV with ISO-8859-1 (latin1) encoding and semicolon (;) as delimiter.
  • Dataset size: 214692 rows and 20 columns.
  • Metrics extracted after analyzing the CSV in OpenRefine:
    • Core entities & volume:
      • Thoroughfares: 8,652 unique streets (COD_VIA).
      • Street Classification: 25 unique street types (VIA_CLASE), with CALLE being the most frequent.
      • Address Point Types: 5 distinct point categories (TIPO_NDP).
      • Administrative Coverage: 21 municipal districts (DISTRITO).
    • Missing values and sparsity:
      • CALIFICADOR: High sparsity with approximately 86% missing values. This field is optional and is used to provide additional information for the address number when applicable.
      • VIA_PAR: 3,798 missing values. This field contains optional particles/connectors that form part of a street name, such as DE or DEL.
      • Core Identifiers: No missing values were found in the main identification and location fields.
    • Schema & Datatype Analysis (Schema):
      • Fields like DISTRITO, BARRIO, COD_VIA, and COD_NDP are encoded as numbers in the raw CSV, but conceptually represent discrete codes/identifiers. Their arithmetic mean is therefore not meaningful so they are mapped to xsd:string.
      • COD_POSTAL is stored as an integer in raw format, but should be cast to xsd:string preserving its 5 digit format because it represents a categorical geographic code rather than a measurement.
    • UTM Coordinates (UTMX_ETRS, UTMY_ETRS): Stored as text strings using European decimal commas (,). They require character substitution to dots (.) to map to xsd:decimal.
    • Geographic Coordinates (LATITUD, LONGITUD): Stored as sexagesimal DMS (degrees, minutes, seconds) text strings. They require parsing and conversion to decimal degrees before being mapped to xsd:decimal, enabling numerical spatial analysis and mapping.
