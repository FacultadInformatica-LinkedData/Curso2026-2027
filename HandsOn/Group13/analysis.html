Dataset Analysis

Group: 13
Dataset: 300614-1-centros-educativos-csv.csv

After cleaning the dataset and using OpenRefine, we have analyzed the schema and characteristics of our dataset 300614-1-centros-educativos-csv.csv.

1.1. Data Schema

The original file consists of 32 columns, of which we kept a main subset of 18 columns, removing those that did not provide relevant information for the final goal and those with a large number of null values.

  • Number of records: 1620 educational centers
  • Number of columns analyzed: 20

These final columns are:

Category Columns
Identification PK, NOMBRE
Classification DESCRIPCION, TIPO, ACCESIBILIDAD, EQUIPAMIENTO
Location and Geometry LATITUD, LONGITUD, BARRIO, DISTRITO, CLASE-VIAL, NOMBRE-VIA, NUM, CODIGO-POSTAL
Contact and Logistics TELEFONO, EMAIL, CONTENT-URL, TRANSPORTE, HORARIO

Column details and RDF usage:

Column Type Description / RDF use
PK integer Unique numeric identifier of the educational center. It will be used as the instance ID.
NOMBRE text Official name of the center (school, secondary school, etc.).
DESCRIPCION, TIPO text Categorization of the center (special education, nursery, upper secondary education).
ACCESIBILIDAD text/integer Accessibility level codes of the center (0, 1, 2, 3, ...).
EQUIPAMIENTO text Specific services and facilities of the center (cafeteria, gym).
TRANSPORTE text Access via public transport (Metro, EMT, Renfe).
LATITUD, LONGITUD decimal Decimal geographic coordinates (WGS84).
BARRIO, DISTRITO text District and neighborhood identifiers. Key for linking (Linked Data).
CLASE-VIAL, NOMBRE-VIA, NUM mixed Components of the physical postal address.
CODIGO-POSTAL integer Postal code (CP 280XX) for geographic searches.
TELEFONO, EMAIL, CONTENT-URL text/URL Direct contact data and official website.

1.2. Data Characteristics and Ranges

The following properties have been identified in the data:

Unique accessibility values

The data are structured with the values 0, 1, 2, 3, 4, and 5, which represent different levels of physical adaptation of the center.

Geographic coordinates

LATITUD ranges approximately from 40.33280700850064 to 40.548576667037935, while LONGITUD ranges from -3.539053333504962 to -3.835524056513188. All points fall within the Madrid area, and all entries are unique.

Completeness

Critical attributes such as the identifier, the name, and accessibility have 0% null values. Other attributes that are very useful for the application, such as transport, have 27 empty entries.

3. Identifier Design and Strategy (URIs)

The base namespace for the entire project will be http://educamadrid.linkeddata.es/.

Ontological model

The concepts and properties that make up the ontology will be under the /ontology/ subdirectory.

  • Base path: http://educamadrid.linkeddata.es/ontology/CentroEducativo#
  • Class example: http://educamadrid.linkeddata.es/ontology/CentroEducativo#EscuelaInfantil
  • Property example: http://educamadrid.linkeddata.es/ontology/CentroEducativo#nivelAccesibilidad

Resources and instances

Individual entities will be placed under /resource/. The primary key (PK) from the original dataset is used as the unique identifier for each school.

  • Pattern: http://educamadrid.linkeddata.es/resource/{OntologicalClass}/{UniqueIdentifier}
  • Educational center example: http://educamadrid.linkeddata.es/resource/School/4916066
  • Neighborhood example: http://educamadrid.linkeddata.es/resource/Neighborhood/el-viso

4. Ontology (Model Summary)

The ontological structure developed for the EducaMadrid project has been encoded in Turtle syntax. All terms in the model operate under the : prefix, which is directly bound to the namespace http://educamadrid.linkeddata.es/ontology/CentroEducativo# .

Main Classes

  • :EducationalCenter
  • :Address
  • :District
  • :Neighborhood
  • :Accessibility

Key Properties

  • :hasAddress (dom: :EducationalCenter, ran: :Address)
  • :inDistrict (dom: :Address, ran: :District)
  • :pk (dom: :EducationalCenter, ran: xsd:integer)
  • :equipment, :transportation (ran: xsd:string)
  • :latitude, :longitude (ran: xsd:double)

Regarding the modeling strategy, we have used a modular architecture that directly inherits from schema.org.
