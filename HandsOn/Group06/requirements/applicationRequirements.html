Application requirements

Madrid Culture Finder helps residents, students and visitors discover nearby libraries and museums, compare access information and consult authoritative facility pages. It will use both selected CSV datasets, later converted to RDF and linked to reviewed external entities.

Dataset requirements

1. Users and scope

A student wants a library in a selected district. A visitor wants museums within a chosen radius. A resident wants facilities with a specific accessibility feature. The first version supports discovery and factual details; bookings, live occupancy, walking routes, real-time opening status and automatic accessibility certification are outside the planned scope.

2. Functional requirements and acceptance criteria

ID Requirement Acceptance criterion
FR01 Unified search
Search both datasets by facility name, ignoring case and accents for search only.		 A name query returns every matching record in the selected facility types.
FR02 Area and type filters
Combine library/museum, district and neighborhood filters; offer an Unknown area option.		 Every displayed record satisfies all active filters; resetting filters restores the full list.
FR03 List and map
Show map markers for valid coordinates and a synchronized result list.		 Selecting a marker highlights its corresponding card; a missing-coordinate record remains in the list with Location unavailable.
FR04 Nearby search
Accept a manually entered latitude/longitude and radius (0.5, 1, 2 or 5 km); optionally request browser location after a user action.		 Results have Haversine straight-line distance within the chosen radius, ordered by distance. Invalid input produces a clear validation message.
FR05 Facility detail
Display address, opening-hours text, transport text, contact, accessibility codes, publisher link and retrieval date.		 Selecting a card opens the corresponding facility, including source text or Not provided for missing fields.
FR06 Accessibility filter
Filter by individual documented codes, distinguishing accessible, partial and unknown status.		 A record containing 1,6 matches both code 1 and code 6; code 6 alone does not match the accessible filter.
FR07 Linked-data context
After RDF conversion and reconciliation, show reviewed links to city, administrative areas and facilities.		 Only verified links appear; unresolved matches are labeled Not linked. Search and details still work without enrichment.
FR08 Empty and error states
Show No matching facilities when filters yield no result, and Data unavailable on load failure.		 The user can clear filters or retry without confusing a load error with an empty dataset.

4. Interaction flow

Search → apply filters → inspect list/map → select a facility → inspect source details and verified links → return with filters retained. Map and list share the selected record. At narrow widths the map follows the list; all results remain accessible without using a map.
