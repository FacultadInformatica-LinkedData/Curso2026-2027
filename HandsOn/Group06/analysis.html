1. Data source analysis

File Records Columns Format Source
libraries.csv 52 32 CSV Ayuntamiento de Madrid
museums.csv 68 32 CSV Ayuntamiento de Madrid

The two files use the same schema. This allows libraries and museums to share a general CulturalSite model while keeping separate classes for each type.

1.2 Schema

Column Type Comments
PK string Identifier for each museum and library.
NOMBRE string Name for each museum and library.
DESCRIPCION-ENTIDAD string Brief description for each museum and library (Some of them have no description).
HORARIO string Days and hours of opening for each museum and library.
TRANSPORTE string Transport methods that are nearby each museum and library.
ACCESIBILIDAD boolean The accessibility of each museum and library. As it can be a combination of numbers from 0 to 6 divided by a comma, each number having a meaning, this column will be separated into 6 columns and each one will have assigned a boolean value depending of the numbers that were in the original column.
CONTENT-URL url Official website containing information of each museum and library.
NOMBRE-VIA, CLASE-VIAL, NUM string Street address of each museum and library. These three columns will be combined into a single one.
CODIGO-POSTAL string Postal code for each museum and library.
COD-BARRIO string Identifier for each neighborhood.
BARRIO string Name of the neighborhood each museum and library is located in.
COD-DISTRITO string Identifier for each district.
DISTRICT string Name of the district each museum and library is located in.
LATITUD decimal The latitude of each museum and library.
LONGITUD decimal The longitude of each museum and library.
TELEFONO string The telephone of each museum and library (Some have to be cleaned as they containg text).
FAX string The fax number of each museum and library (Some have no fax number).
EMAIL string The email of each museum and library.
TIPO string Type of establishment (The data in the column needs to be modified to only get the last word in the text). Only useful in museums as the libraries all have the same type

Some of the columns have not been included in the schema because they contain almost no values or are not necessary.

3. Resource naming strategy

3.1 Base domain and namespaces

The project will use the persistent HTTPS domain https://w3id.org/madrid-culture/. This is different from the default namespace generated by Protégé. The group must register the redirect with w3id.org before public deployment.

Purpose Namespace Prefix
Ontology https://w3id.org/madrid-culture/ontology/ mc:
Individuals https://w3id.org/madrid-culture/resource/ res:

Ontology terms and individuals use different paths. Classes and properties are defined directly under /ontology/. Property URIs are not placed below a class URI.

3.2 Ontology term patterns

Type Pattern Examples
Class https://w3id.org/madrid-culture/ontology/{ClassName} :Facility, :Library, :Museum, :District
Property https://w3id.org/madrid-culture/ontology/{propertyName} :locatedInDistrict, :locatedInNeighborhood, :email

Class local names start with a capital letter. Property local names start with a lower-case letter and use lower camel case.

3.3 Individual patterns

Resource type Pattern Example
Museum /resource/museum/{PK} res:museum/2058
Library /resource/library/{PK} res:library/25526
Address /resource/address/{PK} res:address/1757
Accesibility /resource/accessibility/{PK} res:accessibility/1757
District /resource/district/{COD-DISTRITO} res:district/10
Neighborhood /resource/neighborhood/{COD-DISTRITO}-{COD-BARRIO} res:neighborhood/10-4

Different classes use different paths, for example /museum/ and /library/. Facility names are not used in URIs because names may change. The municipal PK is stable and unique inside each source file. A neighbourhood URI contains both district and neighbourhood code because neighbourhood codes may repeat in different districts.

3.4 URI and publication rules

  • Use HTTPS slash URIs.
  • Use lower-case path segments and ASCII characters.
  • Do not include spaces, accents, file extensions or query parameters in canonical resource URIs.
  • Do not change an existing URI when a name or description changes.
  • When an ontology term is replaced, keep its URI and mark it as deprecated instead of reusing it for another meaning.
