Dataset analysis - Group 04

1. Data and schema analysis

1.1 Real-time air quality dataset

The real-time air quality dataset contains measurements collected by Madrid's air quality monitoring stations. The analysed CSV contains 126 rows and 56 columns.

All records in the analysed snapshot correspond to Madrid (PROVINCIA = 28, MUNICIPIO = 079) and to the same date: 1 October 2026.

This file represents a snapshot of the real-time data source. The application is intended to work with periodically updated versions of the same dataset and is not limited to this specific date.

Schema

  • PROVINCIA: province identifier.
  • MUNICIPIO: municipality identifier.
  • ESTACION: monitoring station identifier.
  • MAGNITUD: code identifying the measured pollutant.
  • PUNTO_MUESTREO: sampling point identifier combining the station code, pollutant magnitude and measurement technique.
  • ANO, MES, DIA: date of the measurements.
  • H01-H24: hourly measurement values.
  • V01-V24: validation codes associated with each hourly measurement.

Each row represents one pollutant measured at one monitoring station during one day. Therefore, a row is not a single measurement: it may contain up to 24 hourly measurements, each one together with its corresponding validation code.

Data characteristics

  • 126 station-pollutant records.
  • 23 different monitoring stations.
  • 11 different pollutant magnitudes.
  • The dataset contains up to 3,024 hourly values (126 rows × 24 hourly fields).

A monitoring station can appear in several rows because the same station may measure several pollutants. For example, a row with ESTACION = 11 and MAGNITUD = 8 represents the NO2 measurements collected by station 11 during that day.

Measurements belonging to different pollutants cannot always be directly compared because they may use different units. For example, CO is expressed in mg/m³ while most of the other pollutants are expressed in µg/m³.

Validation of hourly measurements

Every hourly value must be interpreted together with its corresponding validation field. For example, H01 must be considered together with V01.

A facet over V01 showed 124 records marked as valid (V) and 2 records marked as not valid (N). The invalid records correspond to station 47 for PM10 and PM2.5. In both cases H01 = 0 and V01 = N, so the zero value must not be interpreted as a valid pollutant concentration.

As an example of a valid high value, the maximum actual value found in H01 was 91, corresponding to station 27, MAGNITUD = 12 (NOx), with V01 = V.

1.2 Air quality monitoring stations dataset

The monitoring stations dataset contains metadata and geographic information about Madrid's air quality monitoring network. It contains 24 rows and 25 columns, with one row per station.

Schema

  • Station identification: CODIGO, CODIGO_CORTO and ESTACION.
  • Location: DIRECCION, LONGITUD_ETRS89, LATITUD_ETRS89, ALTITUD, LONGITUD and LATITUD.
  • Projected coordinates: COORDENADA_X_ETRS89 and COORDENADA_Y_ETRS89.
  • Station type: COD_TIPO and NOM_TIPO.
  • Pollutants monitored: NO2, SO2, CO, PM10, PM2_5, O3 and BTX.
  • Street information: COD_VIA, VIA_CLASE, VIA_PAR and VIA_NOMBRE.

Data characteristics

A text facet over CODIGO_CORTO produced 24 different values, and every identifier appears exactly once. Therefore, the dataset contains 24 unique monitoring stations.

1.3 Relationship between the datasets

The datasets can be related through the monitoring station identifier. ESTACION in the real-time dataset corresponds to CODIGO_CORTO in the station metadata dataset.

All 23 station identifiers present in the real-time snapshot have a corresponding entry in the station metadata dataset. The metadata dataset contains 24 stations in total. Station code 55 appears in the metadata dataset but does not appear in the analysed real-time snapshot.

This relationship makes it possible to enrich every air quality measurement with information about its monitoring station, such as its name, address, type, altitude, latitude and longitude.

In summary, the real-time dataset provides information about what was measured and when, while the station metadata dataset provides information about where the measurement was taken.

3. Resource naming strategy

3.1 Domain

The chosen domain is breathemadrid.es, named after the application BreatheMadrid. It is not the default domain provided by Protégé or Chowlk.

3.2 Ontology URI pattern (classes and properties)

Ontology resources use hash URIs under a single namespace:

http://breathemadrid.es/ontology#{ClassName}
http://breathemadrid.es/ontology#{propertyName}

This allows the entire ontology to be served from a single document. Class names start with a capital letter and property names start with a lowercase letter.

Prefix used in Turtle files: @prefix bm: <http://breathemadrid.es/ontology#> .

3.3 Individual URI pattern (instances)

Individuals use slash URIs under a separate path, ensuring a clear separation between the ontology schema and the instance data:

http://breathemadrid.es/resource/{class-path}/{identifier}

Prefix used in Turtle files: @prefix bmr: <http://breathemadrid.es/resource/> .

Each class has its own path segment so that individuals of different classes never share the same URI pattern:

Class URI pattern Example
Municipality resource/municipality/{code} resource/municipality/28079
Station resource/station/{code} resource/station/28079004
StationType resource/stationtype/{typeCode} resource/stationtype/UT
Pollutant resource/pollutant/{magnitudeCode} resource/pollutant/8
Observation resource/observation/{samplingPoint}/{date}/{hour} resource/observation/28079004_10_A/2026-10-01/H01

3.4 Linking to external entities

Municipality individuals are linked to their Wikidata counterpart using owl:sameAs. For example, Madrid is linked to http://www.wikidata.org/entity/Q2807.

3.5 Ontology reuse

The ontology reuses existing vocabularies through rdfs:subClassOf:

  • bm:Station rdfs:subClassOf sosa:Platform
  • bm:Observation rdfs:subClassOf sosa:Observation
  • bm:Pollutant rdfs:subClassOf sosa:ObservableProperty
  • bm:Municipality rdfs:subClassOf dbo:Municipality
