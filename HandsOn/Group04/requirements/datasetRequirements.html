Justification of the Datasets Used

Publisher: Ayuntamiento de Madrid, Dirección General de Sostenibilidad y Control Ambiental. The selected files are:

  • Station metadata CSV: 24 stations and 25 columns. Official dataset page.
  • Hourly measurements CSV: 126 records and 56 columns, covering 1 October 2026. Official dataset page. The local file is a static snapshot, not a continuously updated feed.
R1 – Satisfied. Both datasets belong to the environment domain within a Smart City context. The stations file provides locations and equipment metadata; its X indicators identify monitored pollutants, not concentrations. The measurement file provides hourly pollutant concentrations in Madrid. Together they support urban environmental monitoring and citizen information.
R2 – Satisfied. Both datasets are available in CSV format. They use semicolons (;) as delimiters, which is a standard convention in European CSV files.
R3 – Satisfied. Both official dataset pages linked above identify Creative Commons Attribution 4.0 International (CC BY 4.0). This open license permits redistribution and adaptation, including publication of derived RDF. Publication will credit Ayuntamiento de Madrid, link to the source datasets and license, and indicate modifications such as RDF conversion. The CSV files retain the downloaded data; their exact download time was not recorded.
R4 – Satisfied.

The station dataset contains names, addresses and coordinates of real monitoring stations. The measurement dataset identifies their municipality through PROVINCIA=28 and MUNICIPIO=079. Together these values form the municipality code 28079, identifying Madrid.

The selected external linking target is the municipality of Madrid in Wikidata, with entity URI http://www.wikidata.org/entity/Q2807. Its Wikidata record identifies Madrid as a municipality and gives INE code 28079 (property P772). This provides a concrete code-based match for our local Madrid municipality entity.

During RDF conversion, the local municipality entity can be linked to this external entity using owl:sameAs. Stations will be related to the municipality through a location relation, and observations through their monitoring station. A station or observation must not be declared identical to the city. This identifies the planned links; RDF links have not yet been generated.

The two local CSV files can be joined using CODIGO_CORTO in 212629-0-estaciones-control-aire-csv.csv and ESTACION in calair_tiemporeal.csv, comparing the station codes numerically. For example, code 4 identifies the Plaza de España monitoring station. Alternatively, the station's CODIGO matches the prefix of PUNTO_MUESTREO before the first underscore: 28079004. The ESTACION column in the stations CSV contains a name, not this numeric code.

Addresses and coordinates may support additional links to streets, parks or squares after individual verification. Such places must be distinguished from the monitoring stations themselves; no unverified station-level equivalences are claimed.

R5 – Satisfied. Documentation is available for both datasets: Station file structure describes station fields and equipment indicators; Air quality file interpreter explains hourly records, station and magnitude codes, units and local time. Hourly values H01-H24 must be interpreted together with their corresponding V01-V24 indicators; unavailable or invalid observations must not be treated as zero concentrations. The official real-time source states that automatic readings are pending review and validation.
R6 – Not used (optional). Both selected CSV datasets come from one provider, the Madrid Open Data portal. Multiple source providers are therefore not used. The datasets are complementary and can be joined through station codes. Wikidata is a planned external linking target under R4, rather than a second source of the selected CSV data.
