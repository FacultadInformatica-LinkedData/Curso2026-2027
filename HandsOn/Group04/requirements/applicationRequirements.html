Application Requirements: BreatheMadrid

This document describes the application planned for later course assignments. Hands-on 1 delivers dataset selection, requirements and interface mockups; it does not deliver a working application.

1. Application Description

BreatheMadrid is an application designed to help people in Madrid decide whether it is a good moment to carry out outdoor activities depending on the current air quality.

The user can select an area of Madrid and choose an activity such as running, cycling or walking. The application uses real-time air quality measurements together with the geographical information of the monitoring stations to show the air conditions of the selected area.

The application displays the main pollutant measurements and provides a simple recommendation based on the current air quality. Users can also explore the monitoring stations on a map and open each station to see its location and detailed measurements.

2. Target Users

The application is intended for residents and visitors in Madrid who want to check the air quality before carrying out outdoor activities, especially walking, running or cycling.

3. Data Sources

BreatheMadrid uses two complementary datasets from the Madrid Open Data portal.

  • Real-time air quality dataset: provides pollutant measurements recorded by the monitoring stations.
  • Air quality monitoring stations dataset: provides the name, address and geographical coordinates of each monitoring station.

Both datasets can be connected through the station identifier, allowing the pollutant measurements to be associated with the physical location of each monitoring station.

4. Functional Requirements

The files and external linking plan are detailed in Dataset Requirements. Measurements will be joined using ESTACION and the stations file's CODIGO_CORTO. In the RDF model, observations will reference their stations, and stations their municipality, Madrid, linked to Wikidata Q2807.

  • The user can select an area of Madrid.
  • The user can select an outdoor activity such as running, cycling or walking.
  • The application displays the current air quality information obtained from nearby monitoring stations.
  • The application displays measurements of pollutants such as NO2, PM10 and O3.
  • The application provides a simple recommendation for the selected outdoor activity based on the current air quality.
  • The user can view the air quality monitoring stations on an interactive map.
  • The user can select a monitoring station to view its location and pollutant measurements.
  • The user can filter the information displayed on the map by pollutant.
  • The station detail view shows an hourly trend for the selected pollutant, using only available observations and marking gaps.
  • Every reading displays its unit, timestamp, source and availability status. Pollutants not measured at a station are shown as unavailable.

The user will select a location on the map; stations will be ranked by distance using their decimal latitude and longitude. Availability of the selected pollutant must also be checked. The application will display station observations, rather than claim an exact pollution measurement at the user's location.

The local CSV is a one-day snapshot suitable for the initial prototype. A later live version will periodically retrieve the official feed, display the last successful update and mark stale data. A rolling 24-hour chart requires retaining observations from the previous day; until then, the chart covers only available hours.

Air quality categories will follow a documented official air quality index selected during implementation, with its source and averaging periods stated. Recommendations will use the same categories and display insufficient data when the necessary observations are missing. The mockup values and colors do not define thresholds.

The notification button is an optional future enhancement: a user could opt in to an alert when a selected station's category improves. Notifications are outside the initial prototype scope.

5. User Interface

The main screen shows the air quality information for the selected area and allows the user to choose an outdoor activity. The most relevant pollutant measurements are displayed together with a simple air quality indication.

A second view contains an interactive map showing the monitoring stations in Madrid. The user can filter the stations by pollutant and select one of them.

When a station is selected, the application displays a detailed view containing its name, location and the latest available pollutant measurements.

6. User Interface Mock-ups

The following mock-ups represent the three main views of the BreatheMadrid application.

Illustrative designs: Values, colors, distances, map positions and station labels are examples, not observations extracted from the CSV. The first image includes PM10 and O3 for Plaza de España, and the third includes PM10 for Retiro; these combinations are not supported by the selected station metadata. In the application, those fields will show “Not measured at this station”, or use a suitable station with its name clearly displayed. The “All values validated” footer is placeholder wording and will be replaced with the actual source/availability status; automatic real-time readings must not be presented as finally validated.

6.1 Air Quality and Activity View

This view shows the current air quality, the main pollutant values and the activity selected by the user.

6.2 Monitoring Stations Map

This view allows the user to explore monitoring stations on a map and filter them according to the pollutant being analysed.

Marker numbers illustrate pollutant concentrations, not station identifiers. The implemented map will show the selected pollutant and unit; the “All” view will use category labels rather than mix concentrations of different pollutants.

6.3 Station Detail

This view shows detailed information about a selected monitoring station and its pollutant measurements.

7. Expected Outcome

The expected outcome is an application that makes Madrid air quality data easier to understand and use, helping citizens make more informed decisions before carrying out outdoor activities.
