1. Analysis of the Data Source

1.1 Dataset Description

The dataset selected for this project contains information about the BiciMAD public bicycle stations located in the city of Madrid.

Each row of the dataset represents one BiciMAD station and contains information such as its identifier, name, address, geographic coordinates, number of docking bases and current state.

The dataset contains a total of 631 records and 12 columns. No missing values were found in any of the columns.

1.2 Dataset Schema

Field Data Type Description
OBJECTID Integer Internal identifier of the record.
Activate Integer Activation indicator. Its possible values are 0 and 1.
Address String Postal address of the BiciMAD station.
PosicionSTR String Geographic position represented as a text value.
Ligth Integer Numeric attribute with values between 0 and 3.
Name String Name of the BiciMAD station.
NoAvailable Integer Availability indicator. Its possible values are 0 and 1.
number String Unique station code. It is treated as a string because some identifiers contain letters or other characters, such as 25A, 25B or 508-old.
TotalBases Integer Total number of docking bases of the station.
State String Current operational state of the station.
POINT_X Decimal Longitude of the station.
POINT_Y Decimal Latitude of the station.

1.3 Data Analysis

The OBJECTID field contains values from 1 to 631. The number field uniquely identifies each station and contains 631 different values.

The TotalBases field ranges from 0 to 43 docking bases.

The geographic coordinates are represented using the POINT_X and POINT_Y fields. POINT_X, corresponding to longitude, ranges approximately from -3.784627 to -3.548534, while POINT_Y, corresponding to latitude, ranges approximately from 40.3325463 to 40.5157202.

The State field contains four possible values:

  • IN_SERVICE: 626 stations
  • NOT_IN_SERVICE: 3 stations
  • END_OF_LIFE: 1 station
  • PLANNED: 1 station

The Activate and NoAvailable fields contain binary values (0 or 1).

The Ligth field contains values between 0 and 3. The dataset does not explain the exact meaning of these values, so only the observed range is described.

No null or missing values were found in the dataset.

2. Licensing Analysis

2.1 Publisher and Data Source

The dataset used in this project is the BiciMAD stations dataset. It is published through the Madrid Open Data Portal and its original source is the EMT Madrid Open Data Portal.

The organization responsible for the dataset is Empresa Municipal de Transportes, S.A. (EMT Madrid).

The dataset was published on June 27, 2014.

2.2 Rightsholder

The dataset information page identifies Empresa Municipal de Transportes, S.A. (EMT Madrid) as the organization responsible for the dataset. The dataset page does not mention a different organization as the rightsholder.

2.3 Original Dataset License

The original dataset is published under the Creative Commons Attribution 4.0 International (CC BY 4.0) license.

This license allows the data to be shared and adapted for any purpose, as long as the original source is properly credited.

2.4 Potential License for the Generated Dataset

We will use the same Creative Commons Attribution 4.0 International (CC BY 4.0) license for the generated dataset, because it allows reuse of the data while keeping attribution to the original source.

3. Resource Naming Strategy

3.1 Base Domain

The following base domain will be used for the resources generated in this project:

http://www.example.org/bicimad/

Different paths will be used for ontology resources and individuals.

3.2 Ontology Resources

Classes and properties of the ontology will use the following base URI:

http://www.example.org/bicimad/ontology/

Examples of classes:

  • http://www.example.org/bicimad/ontology/Station
  • http://www.example.org/bicimad/ontology/Location
  • http://www.example.org/bicimad/ontology/StationStatus

Examples of properties:

  • http://www.example.org/bicimad/ontology/name
  • http://www.example.org/bicimad/ontology/address
  • http://www.example.org/bicimad/ontology/totalBases
  • http://www.example.org/bicimad/ontology/hasLocation
  • http://www.example.org/bicimad/ontology/hasStatus

3.3 Individuals

Individuals will use a different path from ontology resources:

http://www.example.org/bicimad/resource/

Different classes of individuals will also use different paths.

Station URI pattern:

http://www.example.org/bicimad/resource/station/{stationNumber}

Example:

http://www.example.org/bicimad/resource/station/25A

Location URI pattern:

http://www.example.org/bicimad/resource/location/{stationNumber}

Example:

http://www.example.org/bicimad/resource/location/25A

Station status URI pattern:

http://www.example.org/bicimad/resource/status/{status}

Example:

http://www.example.org/bicimad/resource/status/in-service

3.4 URI Patterns

Resource URI Pattern
Ontology class or property http://www.example.org/bicimad/ontology/{name}
Station http://www.example.org/bicimad/resource/station/{stationNumber}
Location http://www.example.org/bicimad/resource/location/{stationNumber}
Station Status http://www.example.org/bicimad/resource/status/{status}

The Location class can be used in the future to link BiciMAD stations with other geographic resources.

3.5 Content Negotiation

The same resource can have different representations. For example, a web browser could receive an HTML representation, while a Semantic Web client could receive the data in Turtle format.
