Potential Licence for the Generated Dataset

Creative Commons Attribution 4.0 International (CC BY 4.0)

All the source datasets selected from the Madrid Open Data portal are published under the Creative Commons Attribution 4.0 International (CC BY 4.0) license. This means that the generated dataset can be derived and published under the same license, provided that the creator is credited and the original source is acknowledged. This is the most suitable license for the Linked Data output because it is compatible with academic reuse and attribution.

4. Resource naming strategy

Domain: http://www.madridurbanenvironment.org/

4.1 Ontology resources

Base: http://www.madridurbanenvironment.org/ontology/. Classes use UpperCamelCase and properties use lowerCamelCase.

  • Classes: /ontology/DrinkingFountain, /ontology/Bench, /ontology/PublicToilet, /ontology/Park, /ontology/District, /ontology/Neighborhood
  • Properties: /ontology/status, /ontology/locatedInDistrict, /ontology/locatedInNeighborhood, /ontology/belongsToDistrict

4.2 Individuals

Pattern: http://www.madridurbanenvironment.org/resource/{class-path}/{id}

ClassPathIdentifierExample
DrinkingFountain/resource/drinking-fountain/ID/resource/drinking-fountain/10081659
Bench/resource/bench/ID/resource/bench/100005
PublicToilet/resource/public-toilet/CODIGO ASEO/resource/public-toilet/020035ASW
Park/resource/park/PK/resource/park/50265055
District/resource/district/COD_DISTRITO/resource/district/15
Neighborhood/resource/neighborhood/COD_BARRIO/resource/neighborhood/151

In the parks dataset, the neighborhood code is incomplete: it only contains the neighborhood number within its district. The full code is therefore built as COD-DISTRITO × 10 + COD-BARRIO, matching the codes used in the other datasets. Names are not used for matching because their spelling differs between datasets. Parks with a missing district or neighborhood code (14 of 208) are not linked to a neighborhood.

4.3 Design decisions

  • Ontology and individuals use different paths (/ontology/ vs /resource/).
  • Each class has its own individual path, so individuals of different classes never share a path.
  • Individual URIs depend only on the dataset identifier, not on the class URI, so they remain stable if the ontology changes.
  • Identifiers are kept exactly as in the source data; paths are lowercase and hyphen-separated, without accents or spaces.
  • Pet fountains are the same individuals as in the main fountain file (same ID, verified for all 169 records), so they share one URI; pet use is expressed with intendedUse.

4.4 Content negotiation

  • Slash URIs with HTTP 303 redirects.
  • Accept: text/turtle or application/rdf+xml redirects to http://www.madridurbanenvironment.org/data/{class-path}/{id}.
  • Accept: text/html redirects to http://www.madridurbanenvironment.org/page/{class-path}/{id}.
  • /data/ and /page/ are only redirect targets and are never used as entity URIs.
  • The ontology URI http://www.madridurbanenvironment.org/ontology/ redirects to the Turtle file or to an HTML documentation page.
