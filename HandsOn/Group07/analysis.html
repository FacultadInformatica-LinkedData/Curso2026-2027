Potential Licence for the Generated Dataset

Creative Commons Attribution 4.0 International (CC BY 4.0)

All the source datasets selected from the Madrid Open Data portal are published under the Creative Commons Attribution 4.0 International (CC BY 4.0) license. This means that the generated dataset can be derived and published under the same license, provided that the creator is credited and the original source is acknowledged. This is the most suitable license for the Linked Data output because it is compatible with academic reuse and attribution.

4. Resource naming strategy

Domain: http://www.madridurbanenvironment.org/

4.1 Ontology resources

Base: http://www.madridurbanenvironment.org/ontology/. Classes use UpperCamelCase and properties use lowerCamelCase. Object properties and datatype properties are explicitly distinguished in ontology/ontology.ttl.

  • Classes: ue:UrbanFacility, ue:DrinkingFountain, ue:Bench, ue:PublicToilet, ue:Park, ue:District, ue:Neighborhood
  • Object properties: ue:district, ue:neighborhood, ue:belongsToDistrict
  • Datatype properties: ue:identifier, ue:name, ue:description, ue:status, ue:classification, ue:intendedUse, ue:districtCode, ue:neighborhoodCode, ue:streetType, ue:streetName, ue:streetNumber, ue:postalCode, ue:locality, ue:province, ue:schedule, ue:accessibilityLevel, ue:webPage, ue:utmX, ue:utmY

District and neighborhood references are object properties because their values are individuals. Status, classification, intended use and street type are controlled strings taken from the source, so they remain datatype properties.

Wikidata links present in the with-labels CSVs are published as owl:sameAs IRIs, not as datatype properties. Districts and neighborhoods take their link from the fountain file (the canonical source for both), and parks use same_as_Wikidata_Name. The source has no Wikidata entity for fountains, benches or toilets themselves, so each of those facilities is linked to the Wikidata entity of its most specific administrative unit: the neighborhood for fountains and benches, and the district for toilets (which have no neighborhood column).

4.2 Individuals

Facilities use the Label column produced in OpenRefine. Districts and neighborhoods use the official name exactly as it appears in the DISTRITO and BARRIO columns: the mapping inserts it into an rr:template and RMLMapper percent-encodes spaces and non-ASCII characters (for example, Chamber%C3%AD and Ciudad%20Lineal).

ClassPatternExample
DrinkingFountain/resource/drinking-fountain/{Label}/resource/drinking-fountain/fuente-entrev%C3%ADas-10040811
Bench/resource/bench/{Label}/resource/bench/banco-arapiles-10086220
PublicToilet/resource/public-toilet/{Label}-{CODIGO ASEO}/resource/public-toilet/aseo-avenida-reina-victoria-7-020108AS
Park/resource/park/{Label}/resource/park/huerto-de-las-monjas
District/resource/district/{DISTRITO}/resource/district/Chamber%C3%AD
Neighborhood/resource/neighborhood/{BARRIO}/resource/neighborhood/Arapiles

For fountains and benches the OpenRefine label already ends with the source identifier (for example, fuente-entrevías-10040811), so the identifier is not appended a second time. The 44 park labels are unique. Toilet labels are not always unique (two labels are repeated) and some contain slashes, so the source code is appended to keep every subject unique.

All subject IRIs are built with rr:template, so RMLMapper percent-encodes spaces and non-ASCII characters (for example, fuente-entrev%C3%ADas-10040811, Chamber%C3%AD and Ciudad%20Lineal). Literals keep their UTF-8 characters, so rdfs:label preserves accents (for example, entrevías). Percent-encoded and raw forms are both valid IRIs. The mapping never rewrites the source CSVs.

4.3 Coverage and joins

  • The generated graph contains 22 districts, 132 neighborhoods, 44 parks, 2,309 drinking fountains, 76,617 benches and 130 public toilets.
  • All facilities resolve to a district. All fountains and benches also resolve to a neighborhood; 39 of the 44 parks do (five park rows use non-canonical neighborhood names such as IMPERIAL instead of Imperial), and toilets have no neighborhood in the source.
  • Districts and neighborhoods are built once from the fountain file, which contains all 22 district codes and all 132 neighborhood codes. Every facility links to them with joins, so they are shared individuals rather than repeated literals.
  • The mapping links parks to their district through the official DISTRITO name (44 of 44 match) and to their neighborhood through BARRIO (39 of 44 match). District and neighborhood codes are kept as data with two and three digits respectively (01 to 21, plus 99).
  • Every entity except district 99 carries an owl:sameAs link taken from the with-labels CSVs: 21 of the 22 districts, all 132 neighborhoods, all 44 parks, all 2,309 fountains, all 76,617 benches and all 130 toilets. Facilities reuse the Wikidata IRI of their barrio or district, so the graph has 79,253 owl:sameAs triples but still only 197 distinct Wikidata entities.
  • Pet fountains are not mapped as a separate class: all 169 pet-fountain IDs already appear in the main fountain file with the same label and USO value. Pet use is expressed with ue:intendedUse.

4.4 Data quality and limitations

  • The generated Turtle file is valid UTF-8 and contains no replacement characters; accented Spanish text is preserved as in the source.
  • Park Wikidata URLs in the source use the invalid prefix https://wikidata/entity/. The mapping rewrites them to https://www.wikidata.org/entity/ with a GREL string_replace function.
  • District 99 (OTROS MUNICIPIOS) has no Wikidata link, so 21 of the 22 districts have owl:sameAs; every neighborhood, park and facility has one.
  • Facilities have no Wikidata entity of their own in the source, so their owl:sameAs identifies their barrio (fountains and benches) or district (toilets). This exposes every row's Wikidata column in the graph, but the link identifies the location, not the facility.
  • Two source typos are kept: Aluĉo (U+0109) instead of Aluche in neighborhood names, and SIG?ENZA in one bench street name. Correcting them would require editing the source data, which is out of scope.
  • 73 fountains and 2,403 benches have no street name. They keep the OpenRefine Label (for example, fuente-casco-histórico-de-vallecas-10179827); every facility has exactly one rdfs:label.
  • DESCRIPCION-ENTIDAD contains HTML entities in some rows (8 of the 44 park descriptions include & entities). The mapping copies the value verbatim, so the generated description literals keep those entities.
  • The source DESCRIPCION column contains maintenance notes and doubly escaped entities such as &amp;sup2;; it is not mapped.

4.5 OpenRefine

The openrefine/ directory contains the operation histories for all five datasets:

  • openrefine/updated-histories/: histories that add the Wikidata links.
  • openrefine/histories-with-labels/: histories that add the Label column used for the URIs.

csv/with-labels/ is the output of those histories and the input of the final mapping; csv/csv-updated/ is an earlier intermediate version. The mapping does not modify any CSV file.

4.6 Content negotiation

  • Slash URIs with HTTP 303 redirects.
  • Accept: text/turtle or application/rdf+xml redirects to http://www.madridurbanenvironment.org/data/{class-path}/{label}.
  • Accept: text/html redirects to http://www.madridurbanenvironment.org/page/{class-path}/{label}.
  • /data/ and /page/ are only redirect targets and are never used as entity URIs.
  • The ontology URI http://www.madridurbanenvironment.org/ontology/ redirects to the Turtle file or to an HTML documentation page.
